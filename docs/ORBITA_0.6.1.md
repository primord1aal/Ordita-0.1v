# Орбита 0.6.1+13 — исправления физического теста

ARM64 debug APK. Карты настроены централизованно на защищённый `orbita-maps` шлюз тестового проекта; ввод Geoapify-ключа на телефоне исключён. Шлюз и его квота подготовлены, **до отдельного разрешения облачные операции не выполняются**. Поэтому работающие карты и заказы нельзя считать принятыми до серверного допуска ниже.

## Исправления

- Автоматическая геолокация при открытии рабочего экрана, первое foreground-разрешение Android, без фонового слежения. Повторный системный запрос после отказа не зацикливается. Постоянный запрет открывается через системные настройки. GPS-ответы старше минуты отклоняются; точная GPS-координата сохраняется при ошибке обратного поиска, ручной адрес и существующая поездка защищены.
- Ввод текста отличается от выбранного адреса: причина недоступности заказа объясняется. Сохраняются местный приоритет поиска, выбор на карте и дорожные маршруты.
- Ползунок опущен, зелёная полоса убрана, подтверждение сервера сохранено. Нижняя навигация находится вне формы; keyboard/system insets стабилизированы без ограничения шрифта.
- Настройки содержат тему, системные разрешения и информацию о приложении. Диагностика требует явного `ORBITA_DIAGNOSTICS=true` при сборке; в передаваемом APK она выключена.
- Карта водителя сохраняет камеру при перепроверке роли, не пересоздавая её. Секундный счётчик изолирован от страницы. Одинаковые ответы polling не уведомляют всю страницу; polling и команды сериализуются, ошибки опрашиваются реже. При отсутствии RPC показывается отдельное безопасное сообщение, без технических исключений.

## Производительность

В воспроизводимом Flutter-тесте за 20 секунд покоя, при тех же 7 запросах API, уведомления страницы сократились с **32 до 0**. До: поведение `d0cf764` (добавлен только неиспользуемый clock для совместимости типа с новой панелью). После: текущий контроллер. Секундный текст обновляется отдельно. Это измерение перерисовок состояния, **не Android frame timings**; физическая плавность и CPU/RAM ещё требуют profile-прогона на телефоне.

## Серверный допуск

Read-only проверка подтвердила: диспетчеризация ещё не применена, `orbita_dispatch` отсутствует, история содержит две прежние миграции. Это объясняет ошибку заказов версии 0.6.0+12. Защищённый исполнитель и [необходимый допуск](orders/DISPATCH_060_ACCESS.md) сохраняются; старый SQL не меняется.

Для автоматических карт отдельно подготовлены:

- `supabase/functions/orbita-maps/`: только фиксированные Geoapify endpoints, JWT через Auth, проверка серверного доступа, bounded upstream без redirects/сырых ошибок. Ключ провайдера находится только в Secret сервера.
- `supabase/proposals/20261120173504_managed_maps.sql` (SHA-256 `bf89215b12a25eea37cbb683fe234cfc1f7e217e286f962a6190ede91daa240b`): закрытая таблица квот и `orbita_map_budget`, исполняемый только `service_role`. Атомарный лимит приложения 2500 условных единиц/день на весь проект и 120/минуту на аккаунт. Тайлы/поиск/обратный поиск стоят 1 единицу, маршрут 10. Это консервативный лимит запросов приложения, не гарантия расходов иных ключей/проектов Geoapify.
- Нужны отдельные разрешения на эту миграцию, публикацию Edge Function и установку `GEOAPIFY_SERVER_KEY` в тестовом проекте. Никаких ключей в Git/APK/чате. Тариф автоматически не меняется.

Документация Geoapify подтверждает 3000 credits/day Free и 0.25 credit за тайл; [условия](https://www.geoapify.com/term-and-conditions/) и [тайлы/атрибуция](https://apidocs.geoapify.com/docs/maps/map-tiles/). Шлюз обслуживает только авторизованных пользователей приложения, без открытой перепродажи API. Постоянный/offline-кэш не добавлен; тайлы остаются в прежнем ограниченном RAM-кэше. Привязка ключа к подписи Android не заявляется. Provider account/key API restrictions и пределы расходов должны быть проверены владельцем при выдаче серверного ключа, особенно перед коммерческим запуском.

## Проверка на телефонах после серверного допуска

Установить APK, войти в существующие пассажирский/водительский аккаунты. Проверить первый запрос GPS, отказ/постоянный отказ и настройки; точность маркера/адреса, ручной адрес во время GPS, повтор карты после сбоя. На разных шрифтах проверить клавиатуру/нижнюю навигацию. Выполнить заказ, принять за 25 секунд, пройти статусы, перезапустить оба приложения. Отдельно проверить пропуск/отказ и срок поиска 5 минут. Зафиксировать физическую плавность карты и формы; локальные имитации API и автоматические тесты её не подтверждают.

Защищённый исполнитель квоты карт: `.github/workflows/orbita-maps-migration.yml`. Он допускает только четвёртую миграцию после трёх точных записей истории; Preview проверяет зашифрованную копию и восстановление, Apply сохраняет Auth, заказы, предложения и последовательность очереди. Используется прежний Environment и те же управляющие Variables; отдельное ручное одобрение владельца сохраняется для каждого запуска.

Android CI предварительно загружает ровно три закреплённых артефакта Robolectric (включая Android API 24 и 34) с проверкой SHA-512 по Maven Central и официальному зеркалу Google. Все Android-тесты выполняются; их результаты и lint сохраняются отдельным GitHub artifact. Это устраняет зависимость тестового запуска от неуправляемой загрузки больших JAR внутри Robolectric.
