# Тестовая диспетчерская

Клиент находится в `apps/orbita_admin/dist`. Он обращается к одному тестовому проекту по HTTPS. API-предложение `supabase/proposals/orbita_admin_read_model.sql` читает уже существующие заказы и очередь диспетчеризации. В облаке этот API ещё недоступен.

Клиент использует publishable key и сессию тестового администратора. Ключ клиента указывается в локальном `config.json` по примеру `config.example.json`. Токен живёт в памяти открытой вкладки. При выходе или запрете серверного чтения данные убираются с экрана. Разрешение на чтение проверяют текущая Auth-сессия и роль в серверных таблицах. Состояние вкладки или поле роли в JWT не дают права читать заказы.

Снимок возвращает до 50 активных заказов, 50 завершённых записей и 50 водителей. Место в очереди вычисляет сервер для ожидающих водителей по тем же полям, которые использует подбор. Занятые водители и водители с предложением остаются в списке без номера очереди. Адреса активных заказов видит администратор. Контакты, координаты и тела Auth-ответов в снимок не входят. Локальные проверки охватывают запреты пассажиру и водителю, блокировку администратора, отозванную сессию, порядок очереди и предел истории.

## Управление и телефонный заказ

`orbita_admin_operations.sql` добавляет ограничение новых предложений, список водителей и журнал действий. Действующая поездка сохраняется, а линия ограниченного водителя закрывается при её завершении. При снятии ограничения водитель сам возвращается на линию. Повтор с тем же идентификатором возвращает прежнее подтверждение без повторного действия или второй записи.

`orbita_admin_phone_orders.sql` подключает к той же очереди телефонный заказ для существующего разрешённого аккаунта пассажира. Диспетчер вводит UUID и подтверждённые адреса с координатами. Общий срок поиска — пять минут. Повтор с теми же данными не создаёт второй заказ. Журнал хранит служебные IDs, время и вид действия. В нём нет адресов, номеров телефонов и паролей.

## Закрытое размещение

После Maps Apply потребуется отдельный проверяемый допуск к DDL панели. Предложение чтения добавляет индекс истории, поэтому его применение идёт после проверки и применения квоты карт. Схему `orbita_admin_api` добавляют в разрешённые Data API схемы тестового проекта, сохраняя существующие. Внутренняя `orbita_admin_private` остаётся закрытой.

Статические файлы `dist` предназначены для отдельного закрытого HTTPS-адреса владельца. Доступ к адресу ограничивает частная сеть или авторизующий шлюз. Сохранить политику соединений CSP из шаблона и установить серверный `Content-Security-Policy` с `frame-ancestors 'none'`. `config.json` создаётся на закрытом хосте по примеру и содержит только publishable key тестового проекта. В панели дополнительную проверку роли выполняет PostgreSQL. Действующий лендинг и его ссылки для размещения панели не используются.

После отдельного допуска предложения применяют по порядку `orbita_admin_read_model.sql`, `orbita_admin_operations.sql`, `orbita_admin_phone_orders.sql`. При облачной приёмке проверить вход, отказ пассажиру и водителю, отзыв тестовой сессии, сохранение принятой поездки при ограничении, повтор телефонного заказа и согласованность с телефонами. Локальные проверки используют синтетические данные. Облачные Auth и PostgREST потребуют отдельной проверки.
