Проверены реальные LOGIN `anon/authenticated`, отсутствие superuser/BYPASSRLS/владения таблицей, ACL и RLS, запрет private helpers, роль и блокировка после ожидания mutex, срок/привязка/отзыв сессии, нормализация всех оговорённых пробелов, точное содержимое повторного запроса, два конкурентных одинаковых и разных ключа, собственность, повторная отмена и отмена по сроку, восстановление последнего результата и настоящий `statement_timeout` с откатом.

**Dart: 14 целевых проверок успешно.** Проверены сериализация стабильного intent, владелец и ожидаемый ID, неизвестные версии/состояния/поля, координаты, UTC и микросекунды, некорректная календарная дата, граница deadline, состояние отмены и нормализация Unicode.

**Существующая защита миграций:** целевой `test_changed_or_extra_migration_fails_before_connection` успешно пройден; лишняя/изменённая runnable migration по-прежнему отклоняется до соединения.

**Общий Flutter-анализ: без замечаний.** Прежние 409 Flutter-проверок не повторялись: принятый runtime карты/входа не менялся, новые модели проверены целевым набором. APK для ещё не применённой схемы не собирался.

## Локальная среда и её пределы

Два Docker-варианта PostgreSQL остановились при распаковке из-за нехватки места в storage daemon; контейнеры не запускались. sudo/scoped installer в среде отсутствует. Для тестов использованы **PostgreSQL 17.11** и клиент из официальных Debian security пакетов `17.11-0+deb13u1`, извлечённых в пользовательский рабочий каталог. Системные пакеты/репозитории не менялись; InRelease проверен системным Debian keyring, SHA-256 пакетов — по этому подписанному индексу, HTTPS/TLS сохранены.

Стенд создаёт собственный временный кластер, private Unix socket 0700, `listen_addresses=''`, реальные несуперпользовательские подключения. TCP выключен. Все данные синтетические. После тестов сервер остановлен, принадлежащий тесту кластер удалён. Это реальная PostgreSQL, а не mock SQL; модель claims не проверяет JWT-подпись, Auth HTTP и PostgREST.

Независимое узкое чтение кандидата до единственного изменения COLLATE не нашло дефектов в проверенных guards/правах/гонках/идемпотентности/deadline. После COLLATE повторены тесты Unicode и canonical replay; остальные успешные сценарии не дублировались.

## Что требуется для подключения

1. Точечно подготовить допуск **второй** миграции через установленный защищённый процесс. Нынешний исполнитель разрешает только первую миграцию с пустой историей и этот кандидат не применит. Обход проверки/перезапись старого lock.json не выполняются.
2. До облачного применения повторно сверить исходную историю `[202611050001]`, отсутствие новых объектов, актуальные определения зависимостей; зафиксировать target ref, SHA SQL, проверенный план восстановления и отдельный допуск владельца.
3. Только после успешного применения проверить настоящие Auth/JWT/PostgREST RPC на разрешённом тестовом проекте. Другие проекты не затрагиваются.
4. Подключить Flutter repository/controller, сохранение pending intent до отправки, восстановление собственной квитанции и отмену. Тестовый режим должен прямо сообщать, что водитель не вызывается. Затем собрать подключённый APK для испытаний владельцем.

Это готовая локальная заготовка серверного блока и контракт границы приложения; работающий серверный заказ в установленном APK ещё не заявляется. Линия/очередь/Push и рабочая обработка реальных пассажиров не начинались.
