# Орбита 0.5.4+6 — единый пакет правок интерфейса

Дата отчёта: 10 ноября 2026 года. База — `f884e57f5a5f17b800210c223765a3a7dd359dad`, рабочая ветка — `codex/orbita-stage-3b-auth`. Это накопленные правки после проверок авторизации, а не переход к картам и заказам.

## Что изменилось

- Удалён промежуточный экран выбора пассажира/водителя. После заставки сразу доступна форма входа, а интерфейс выбирается по прежней серверной роли. Новая регистрация не добавлялась.
- Тёмная заставка использует существующее зелёное кольцо, плавное движение и системную настройку уменьшения анимации. Нет искусственного ожидания. При медленном восстановлении появляется «Подключаемся…», при ошибке — понятное сообщение и «Повторить». Нативная Android-заставка также получила тёмный фон.
- При действующей сессии форма входа не мигает между запуском и открытием интерфейса. Пароль можно показать/скрыть; после отправки он удаляется из поля.
- Блокировка показывает сообщение на форме входа. Временная ошибка связи закрывает рабочий доступ, сохраняя прежнюю защищённую сессию для повторной проверки.
- Неизменные пользователь и роль после периодической проверки сохраняют вкладку и введённый адрес. Пока результат ожидается, действия закрыты. В фоне интерфейс закрывает непрозрачный слой. Реальная смена/потеря доступа закрывает прежние экраны, включая вложенные маршруты.
- Профиль содержит аккаунт, роль, «Выйти», настройки, один пункт «Проверка устройства» и версию. Слова «телефон» для обозначения устройства заменены. Публичного переключения интерфейса нет.
- В «Проверке устройства» сохранены уведомления, геолокация и фоновая служба: разрешения, двухшаговый запрос геолокации, тестовое уведомление, запуск/остановка, дополнительные сведения. API доступно через «Расширенная диагностика» только в debug-сборке. Это не обход авторизации и не дополнительные серверные права.
- Число обновлений позиции и время последней позиции/сигнала службы подписаны раздельно. Координаты по-прежнему не сохраняются и не отправляются.
- У корневой формы нет бесполезной стрелки. Вложенные экраны возвращаются назад; системный Back из профиля/истории переводит на основную вкладку. Возврата в удалённый выбор роли нет.
- Форма ограничена удобной шириной на планшете, прокручивается при клавиатуре и крупном шрифте. Системное масштабирование не ограничивается.

## Защита и сохранённые механизмы

`SupabaseAuthRepository`, secure storage, обновление сессии, серверная проверка роли, тайм-ауты, отмена рабочих операций и защита от поздних ответов сохранены. Новое состояние представления существует только в памяти. Оно не является источником полномочий: на перепроверке реальные `access`, `canUseRole` и `guardAction` остаются закрыты. В тестах это проверяется отдельно от нажатий на экран.

Нет изменений SQL, RLS, административных функций, миграционных инструментов, GitHub workflow, Variables, Secrets, Environment, `main` или старого прототипа. Для этого пакета не нужны Preview/Apply/Inspect, повторная миграция или обновление SHA миграционного допуска. Android-служба и её разрешения не изменены.

## Проверки и их границы

- Формат Dart и `flutter analyze --fatal-infos --no-pub`: успешно.
- Полный набор Flutter и существующий build guard: **192 теста прошли**, без облачной конфигурации, в сетевом пространстве только с loopback и без маршрута во внешнюю сеть. Auth и устройство в них искусственные.
- Для регрессии вкладки сначала запущен тот же тест на исходниках F884: он упал, потому что профиль исчезал во время перепроверки. На исправленном коде тест прошёл. Подтверждены сохранение введённого адреса и запрет действий до результата.
- Проверены восстановление без промежуточной формы, успешный вход/ошибка/выход, роль администратора и закрытые состояния, блокировка, отзыв/смена роли, сетевая ошибка/повтор, тайм-аут и поздний ответ, Back, уникальные функции диагностики, крупный шрифт и клавиатура на планшете.
- Сгенерированы **54 модельных снимка** с настоящими шрифтами SDK: 6 экранов × 3 размера (360×800, 800×1280, 1280×800) × 3 масштаба (1, 2, 3.2). Выборочно просмотрены форма, крупный шрифт, профиль и диагностика в горизонтальном режиме. Это не фотографии Android-устройств.
- Локальный ARM64 debug APK без облачной конфигурации собран. Android `:app:testDebugUnitTest`: **19 тестов**, без ошибок и пропусков. `:app:lintDebug`: без ошибок, 7 предупреждений (версии инструментов, избыточный каталог ресурсов `v21`, рекомендации KTX). Первая сборка обнаружила ошибку формата цвета в новом Android-ресурсе заставки; ресурс исправлен, повторная сборка прошла. Gradle сообщает об устаревающих возможностях для будущего Gradle 10; закреплённый Gradle 9.3.1 успешно выполняет проверки.

Владелец уже подтвердил Auth-сценарии предыдущей сборки +5 на Teclast T50 Plus / Android 16 и предоставил реальный успешный клиентский API-отчёт 13/13. Короткий сценарий восстановления после ожидания также подтверждён владельцем; значение JWT expiry возвращено к 3600 секундам. Значения `exp/iat` и сам HTTP-запрос refresh отдельно не перехватывались. Эти факты не выдаются за аппаратную проверку нового пакета +6.

## Что ещё не готово

Новый интерфейс +6 ещё не принят на физическом устройстве. Android 7–13, устройство без Google-сервисов, TalkBack и длительная геолокация под блокировкой 10/30/60 минут не проверены этим пакетом. Карты, настоящие заказы, рабочая очередь, серверный Push и полноэкранное окно заказа поверх блокировки не добавлены. Администратор по-прежнему получает нейтральный экран; отдельная веб-панель этим пакетом не создаётся.

Тестовые APK имеют debug-подпись. У разных запусков Actions она может отличаться: обычное обновление поверх прежней установки возможно только при совпадении сертификата. Удаление старой установки сбрасывает локальный вход и разрешения и требует отдельного согласования. Настройка постоянного ключа не включалась в этот пакет.

APK появляется в артефакте `ORBITA-0.5.4-auth-preparation-apk` успешного обычного push-запуска для итогового коммита этой ветки. Сам факт сборки не подтверждает доступность облачного API или работу фонового режима на устройстве.
