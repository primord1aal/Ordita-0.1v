# ОРБИТА 0.5.4 · сборка 6 — вход и интерфейс

Это тестовый ARM64 debug APK из `codex/orbita-stage-3b-auth`, версия **0.5.4+6**. В профиле и на форме входа указана «сборка 6». Минимум — Android 7 / API 24 по совместимости закреплённого Flutter SDK. Android 7–13 и устройство без Google-сервисов на практике не проверены.

В согласованном тестовом проекте уже применена миграция авторизации, созданы тестовые аккаунты. Владелец подтвердил вход, восстановление сессии, выход, смену и отзыв роли, блокировку и восстановление связи в предыдущей сборке **+5** на Teclast T50 Plus с Android 16. Эти результаты не заменяют проверку нового интерфейса **+6** на устройстве. Повторно применять миграции для этой APK не требуется.

Артефакт GitHub Actions `ORBITA-0.5.4-auth-preparation-apk` содержит `ORBITA-0.5.4-auth-preparation.apk`, `SHA256SUMS.txt`, эту инструкцию и справочные документы. Название файла сохранено для совместимости с существующим workflow. Скачивать артефакт нужно из успешного запуска для **нового коммита**, а не из Preview/Apply или прежней сборки. Нужен вход в GitHub; срок хранения — 14 дней. `STAGE_3B_APPROVAL_PACKAGE.md` в архиве — исторический пакет подготовки миграции, не инструкция повторять её сейчас.

APK подписывается тестовым ключом. У разных запусков GitHub Actions debug-подпись может различаться. При несовпадении Android откажется обновлять установленное приложение. **Не удалять старую установку без отдельного согласования:** удаление сбросит локальную сессию и разрешения. Серверный тестовый аккаунт при этом сохраняется. Стабильная подпись для обновлений — отдельная задача; ключи подписи в этом пакете не менялись.

Изменённые сценарии:

- Без сессии: тёмная заставка → сразу форма входа; публичного выбора ролей нет. Пароль можно показать и скрыть.
- С действующей сессией: заставка → интерфейс по серверной роли. Нет искусственной задержки и промежуточной формы входа. Администратор видит предусмотренное нейтральное состояние.
- При блокировке: форма входа с сообщением. При временной ошибке сети сессия сохраняется; доступ восстанавливается через «Повторить».
- Обычная успешная перепроверка неизменных прав сохраняет открытую вкладку и введённый адрес. Пока проверка идёт, рабочие действия закрыты. Настоящая смена или потеря доступа закрывает прежний интерфейс.
- Профиль → **Проверка устройства**: уведомления, геолокация, фоновая служба. В тестовой debug-сборке внутри есть **Расширенная диагностика → Проверка API**. Двухшаговые разрешения, тестовое уведомление и запуск/остановка службы сохранены.
- «Выйти» завершает локальный вход; Back из вложенного экрана возвращает назад, из профиля — на главную вкладку.

Для приёмки нового пакета достаточно проверить перечисленные изменения на своём устройстве, включая крупный шрифт, поворот планшета и сохранение вкладки после очередной проверки доступа. Не требуется заново повторять каждый уже подтверждённый серверный тест. Подробности реализации и проверок — [отчёт](https://github.com/primord1aal/Ordita-0.1v/blob/codex/orbita-stage-3b-auth/docs/ANDROID_0.5.4_UX_BATCH.md).

Серверный Push, карты, настоящие заказы и линия ещё не подключены. Нет полноэкранного окна заказа поверх блокировки. Длительная фоновая геолокация 10/30/60 минут остаётся отдельной проверкой; инструкция для HiOS — [ANDROID_STAGE_2.md](https://github.com/primord1aal/Ordita-0.1v/blob/codex/orbita-stage-3b-auth/docs/ANDROID_STAGE_2.md). Работа службы при заблокированном экране не подтверждается одними widget-тестами.

Не передавать пароли, Access/Refresh Token или сырые Auth-ответы в чат. Диагностический журнал API копирует только разрешённые поля.
