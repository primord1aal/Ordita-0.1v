## Что исправлено

1. SQL-чтения Preview/Inspect выполняются в явной READ ONLY-транзакции с серверными `SET LOCAL`: при обычном чтении statement timeout 30 секунд, lock timeout 5 секунд, idle-in-transaction timeout 15 секунд. Метка операции также задаётся внутри транзакции. Startup-параметры, которые pooler может не передать серверу, не считаются доказательством защиты.
2. Клиент только чтения отказывает в любом облачном запуске CLI, включая dry-run. В Preview облачная часть выполняет только фиксированные чтения и native `pg_dump`, открывающий собственную READ ONLY-транзакцию.
3. Экспорт шифруется AES-256, расшифровывается обратно, проверяется SHA архива. Для восстановления используется дамп именно из проверенного расшифрованного архива.
4. Восстановление и CLI dry-run выполняются в собственном PostgreSQL-контейнере с `--network none`, без опубликованных портов, с проверкой точного CID/метки и локальным TLS `verify-full`. Облачные пароль, URL и API-токены туда не передаются. Копируются только проверенный CLI, фиксированная конфигурация без seed и единственный файл миграции с проверкой SHA.
5. История восстановленной копии сравнивается с прочитанной облачной историей. CLI должен показать ровно `202611050001_stage3b_auth.sql`; проверяемое состояние копии и история после dry-run должны остаться прежними. Отчёт явно содержит `cli_dry_run_target=isolated_restored_snapshot`.
6. После подготовки копии облачное состояние/отпечаток читаются повторно. Изменение состояния, ошибка/таймаут CLI или неподтверждённое удаление собственного контейнера запрещают успешный отчёт. Повторного запуска нет; чужой контейнер удалять нельзя.
7. В CI добавлен настоящий локальный Supavisor. Облачные условия запуска, допуск Environment, проверки SHA/Ref/TLS и пять зафиксированных URL Session pooler сохранены. Новых Secrets, Variables, ролей БД или доступов не требуется.

Путь применения остаётся отдельным механизмом. Ужесточена проверка его входного отчёта: старый Preview без подтверждения локального плана не принимается. Это не разрешение Apply.

## Что остаётся проверить

- **Первый новый Cloud Preview:** реальный экспорт из выбранного Supabase, цепочку доверия endpoint/CA и прохождение всей процедуры. Локальный Supavisor воспроизводит нужное поведение, но не заменяет проверку конкретного управляемого сервиса. Inspect №19 проверял только чтение.
- **Остановка на сервере:** клиентский таймаут, закрытие соединения или удаление контейнера не доказывают мгновенного исчезновения удалённого backend. SQL-чтения имеют серверные таймауты; `pg_dump` работает read-only и имеет lock wait timeout/клиентский предел. Нельзя обещать общий серверный deadline всего экспорта через pooler. Неизвестный результат требует разбора, без автоматического повтора. Облачный CLI в Preview полностью устранён.
- **До Apply:** отдельно подтвердить надёжные серверные ограничения облачного CLI через Session pooler либо согласовать другой безопасный путь применения. Startup-настройки через pooler недостаточны. Текущая подготовка этого не решает; Apply не объявляется готовым.
- **Границы копии:** restore использует минимальную модель Auth и `--no-owner --no-privileges`. Он не доказывает восстановление владельцев/ACL, управляемых Auth/Storage, файлов Storage, полномочий/паролей ролей, настроек сервиса или PITR. Dry-run на снимке не исполняет SQL миграции и не подтверждает облачные права, блокировки или RLS.
- **Хранение:** шифрование защищает содержимое артефакта, но не его доступность. Владелец должен скачать копию до Apply, сверить SHA и хранить файл отдельно от фразы вне GitHub; срок артефакта — 14 дней.

Миграции, аккаунты и настройки облака до этого не меняются. [Полная процедура и действия при ошибке](STAGE_3B_MIGRATION_RUNBOOK.md).
