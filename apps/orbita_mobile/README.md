Этап 2, версия **0.5.0**, тестовый идентификатор **ru.orbita.taxi.dev**. Только Android: просмотр интерфейса и диагностика телефона, без рабочих заказов.

## Сборка

Закреплены Flutter **3.47.9** (`c197ca5199e9ee5661e865596c9c07294dfab51c`), Dart **3.13.7**, JDK **17**, compile/target SDK **36**, NDK **28.2.13676358**, Gradle **9.3.1** с контрольной суммой. Зависимости — в `pubspec.lock`.

Минимум **API 24 / Android 7** соответствует нижней границе этого Flutter SDK. Android 7–13 на физических устройствах не проверены. Единственный заявленный телефон — Tecno KL7, Android 14, HiOS 14.5.0 с RuStore и Google; результаты его испытаний ожидаются. Отсутствие Google отдельно не проверено.

Из `apps/orbita_mobile/`:

```sh
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib test
flutter analyze --fatal-infos
flutter test --reporter expanded
flutter build apk --debug --no-pub --split-per-abi --target-platform android-arm64
```

Из `apps/orbita_mobile/android/`:

```sh
./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug
```

APK: `build/app/outputs/flutter-apk/app-arm64-v8a-debug.apk`. Для Tecno собирается ARM64-вариант, чтобы не включать ненужные ему архитектуры. На 32-битный Android эта APK не устанавливается; другие архитектуры можно собрать отдельно после согласования испытаний. Подпись debug, не коммерческая. Локальные SDK, пути и ключи в Git не входят; `local.properties` создаётся Flutter для конкретного компьютера.

Workflow `.github/workflows/orbita-android.yml` выполняет проверки и сохраняет `ORBITA-0.5.0-test-apk`: APK, SHA-256 и инструкцию. Для сборки не нужны Supabase или секреты.

## Исходники и границы

- `lib/src/app.dart` — русская локаль, тема, навигация.
- `lib/src/screens/` — просмотр пассажира/водителя, диагностика.
- `lib/src/domain/contracts.dart` — отдельные типы просмотра и серверной роли; контракты сессии/Push; клиентская политика завершения поездки при ограничении.
- `lib/src/services/session_store.dart` — адаптер защищённого хранения будущей сессии, сейчас без реальных записей.
- `lib/src/platform/device_gateway.dart` — Android-мост и раздельные явные действия для разрешений.
- `android/app/src/main/kotlin/ru/orbita/taxi/dev/` — уведомления, разрешения и локальная служба `location`.
- `test/` — Flutter-тесты с явной тестовой платформой.
- `android/app/src/test/` — модельные проверки Android 14 через Robolectric.

Просмотр роли не является авторизацией. `BackendConfiguration` проверяет форму HTTPS URL и публичного ключа, но не подключается и не подтверждает ключ. Запросов к серверу заказов нет.

При будущей интеграции роль должна читаться с сервера через `SessionRepository`. Непрозрачная сессия хранится через `SecureSessionStore`; серверные ключи и копия доверенной роли туда не помещаются.

`OrderPushGateway` отделяет будущий RuStore/FCM от локальной проверки. Реальный обработчик обязан проверять событие, заказ, предложение и срок на сервере, исключать повторы и не принимать заказ автоматически.

## Android 14

`LocationDiagnosticService` не экспортируется, имеет тип `location`, запускается явно из видимого Activity. Объявлены `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`; есть постоянное уведомление и остановка.

Сначала foreground fine/coarse; отдельный необязательный background-шаг предваряется пояснением. Android 11+ открывает настройки. Для ручного запуска достаточно «Только при использовании». Приблизительный доступ учитывается, прямой зависимости службы от Google SDK нет.

Сохраняются только время запуска/сигнала/измерения и счётчик, без координат и сети. `START_NOT_STICKY`: нет автоматического старта после перезагрузки или уничтожения процесса. Получение позиции зависит от системных провайдеров; отсутствие фикса не равно остановке службы.

Полноэкранные уведомления не используются. Настоящие Push, передача координат, карты, вход и заказы относятся к следующим этапам. Физические испытания не подменяются модельными тестами.
