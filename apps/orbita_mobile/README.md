## Сборка

Закреплены Flutter **3.47.9** (`c197ca5199e9ee5661e865596c9c07294dfab51c`), Dart **3.13.7**, JDK **17**, compile/target SDK **36**, NDK **28.2.13676358**, Gradle **9.3.1** с контрольной суммой. Зависимости — в `pubspec.lock`.

Минимум **API 24 / Android 7** соответствует нижней границе этого Flutter SDK. Android 7–13 на физических устройствах не проверены. Tecno KL7 / Android 14 / HiOS 14.5.0 с RuStore и Google — устройство ранних проверок интерфейса и диагностики; текущие результаты авторизации +5 относятся к планшету Teclast T50 Plus / Android 16. Формальная серия связи 0.5.3 и длительная геолокация 10/30/60 минут не закрыты. Устройство без Google-сервисов не проверено.

Из `apps/orbita_mobile/`:

```sh
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib test tool
flutter analyze --fatal-infos
flutter test --reporter expanded
dart tool/test_build_guard.dart
flutter build apk --debug --no-pub --split-per-abi --target-platform android-arm64
```

Из `apps/orbita_mobile/android/`:

```sh
./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug
```

APK: `build/app/outputs/flutter-apk/app-arm64-v8a-debug.apk`. Собирается ARM64-вариант для тестовых устройств; на 32-битный Android эта APK не устанавливается. Команда выше без клиентской конфигурации создаёт неподключённую сборку: она проверяет компиляцию, но не обеспечивает настоящий вход. Подключённый APK выпускает CI после проверки разрешённых Variables. Подпись debug, не коммерческая; у разных запусков ключ может различаться, поэтому обновление поверх прежней установки не гарантировано. Локальные SDK, пути и ключи в Git не входят; `local.properties` создаётся Flutter для конкретного компьютера.

Workflow `.github/workflows/orbita-android.yml` выполняет проверки и сохраняет `ORBITA-0.5.1-test-apk`: APK, SHA-256 и инструкцию. Запускается для мобильных изменений в Android-основе и `codex/orbita-ui-refinement`, а также Pull Request. Для сборки не нужны Supabase или секреты.

Для текущей ветки используется отдельный `.github/workflows/orbita-stage-3b.yml`: Flutter/CLI-тесты без внешней сети, регрессионная компиляция и Android-проверки, затем обязательная проверка четырёх Variables и подключённый диагностический APK. Отсутствие конфигурации останавливает выдачу APK; фиктивные значения не подставляются. Старый workflow не изменён.

## Исходники и границы

- `lib/src/app.dart` — русская локаль, тема, навигация.
- `lib/src/screens/auth_screen.dart` — заставка, единая форма входа и маршрутизация по проверенной роли.
- `lib/src/screens/preview_screens.dart` — существующие пассажирский/водительский интерфейсы и профиль; публичного выбора роли больше нет. Карты и заказы по-прежнему обозначены как неподключённые.
- `lib/src/backend/` — проверка положительного списка конфигурации и ограниченный GET health без аккаунтов, редиректов, записей в базу или вывода ключа.
- `lib/src/backend/probe_journal.dart` — белый список полей копирования, без тела ответа/ключа/сетевого handle и без постоянного файла.
- `lib/src/platform/network_observer.dart` и Android `NetworkSupport` — снимки активной сети; оператор/DNS отмечаются владельцем. Отсутствие достоверного определения остаётся «Не определено».
- `lib/src/services/api_check_controller.dart` — последовательные пробы, сравнение выбранной/активной сети, блокировка неподходящих условий и журнал процесса.
- `lib/src/ui/` — единая тема, фирменное кольцо и адаптивные компоненты без ограничения системного шрифта; высота растёт по содержимому.
- `lib/src/services/device_check_controller.dart` — единый снимок устройства, последовательные действия, обновление после возврата из настроек, отдельные ошибки. Уход со страницы не останавливает Android-службу.
- `lib/src/domain/contracts.dart` — отдельные типы просмотра и серверной роли; контракты сессии/Push; клиентская политика завершения поездки при ограничении.
- `lib/src/services/session_store.dart` — адаптер защищённого хранения сессии; `auth/secure_auth_storage.dart` связывает его с Auth SDK.
- `lib/src/platform/device_gateway.dart` — Android-мост и раздельные явные действия для разрешений.
- `android/app/src/main/kotlin/ru/orbita/taxi/dev/` — уведомления, разрешения и локальная служба `location`.
- `test/` — Flutter-тесты с явной тестовой платформой.
- `android/app/src/test/` — модельные проверки Android 14 через Robolectric.
- `tool/capture_ui_test.dart` — снимки модели с настоящими шрифтами SDK и вымышленными показателями; не часть обычного набора тестов и не фотографии реального устройства.

`BackendConfiguration` проверяет форму HTTPS URL и публичного ключа, но сама не подключается и не подтверждает ключ. Рабочий интерфейс открывается только после существующей серверной проверки доступа. В тестах роль выдаёт явный `FakeAuthRepository`; в продукте такого переключателя нет. Запросов к серверу заказов нет.

Текущая авторизация использует `AuthRepository`, `AuthController` и `SupabaseAuthRepository`, а не прежний неподключённый контракт `SessionRepository` этапа 2. Явный `SecureAuthStorage` совместим с SDK LocalStorage и пишет сессию через `SecureSessionStore`; серверные ключи и копия доверенной роли туда не помещаются. Используется SupabaseClient без глобального Supabase.initialize/скрытого восстановления; истёкшая сессия обновляется прежним механизмом. Временная ошибка закрывает роль, сохраняя сессию. Никаких прав из metadata/дискового кэша.

На время перепроверки контроллер удерживает только представление последнего подтверждённого интерфейса. Реальные `access`, `canUseRole` и `guardAction` остаются закрыты; старые операции отменяются как прежде. Успех для того же пользователя и роли не пересоздаёт вкладки; ошибка, отзыв или смена роли закрывают старый интерфейс и вложенные маршруты. В фоне интерфейс закрыт непрозрачным слоем. Снимок представления не сохраняется на диск и не выдаёт права.

`OrderPushGateway` отделяет будущий RuStore/FCM от локальной проверки. Реальный обработчик обязан проверять событие, заказ, предложение и срок на сервере, исключать повторы и не принимать заказ автоматически.

## Android 14

`LocationDiagnosticService` не экспортируется, имеет тип `location`, запускается явно из видимого Activity. Объявлены `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`; есть постоянное уведомление и остановка.

Сначала foreground fine/coarse; отдельный необязательный background-шаг предваряется пояснением. Android 11+ открывает настройки. Для ручного запуска достаточно «Только при использовании». Приблизительный доступ учитывается, прямой зависимости службы от Google SDK нет.

Сохраняются только время запуска/сигнала/измерения и счётчик, без координат и сети. `START_NOT_STICKY`: нет автоматического старта после перезагрузки или уничтожения процесса. Получение позиции зависит от системных провайдеров; отсутствие фикса не равно остановке службы.

Полноэкранные уведомления не используются. Настоящие Push, передача координат, карты и заказы относятся к следующим этапам. Физические испытания новой сборки и длительной работы службы не подменяются модельными тестами. Сборка 6 не меняет службу, разрешения, Supabase или миграции.

## Проверка интерфейса

`responsive_test.dart` проверяет экраны шириной 320–412 логических точек и короткую горизонтальную область, масштабы 1 / 1.5 / 2 / 2.5 / 3.2, клавиатуру, длинные будущие адреса, семантические подписи и доступность вкладок. `auth_navigation_test.dart` добавляет восстановление, блокировку, смену роли, сохранение вкладки и планшетную форму 800×1280 / 1280×800 с клавиатурой и шрифтом до 3.2. Это линейная модель масштабирования; реальный масштаб Android и TalkBack проверяются отдельно на устройстве.

Для визуального просмотра разработчиком (не нужно владельцу для установки) задать `ORBITA_FLUTTER_FONT_DIR` в каталог `bin/cache/artifacts/material_fonts` своего Flutter SDK и при желании `ORBITA_UI_CAPTURE_DIR`, `ORBITA_CAPTURE_WIDTH`, `ORBITA_CAPTURE_HEIGHT`. Затем `flutter test tool/capture_ui_test.dart --reporter expanded`. По умолчанию PNG сохраняются в игнорируемый `build/ui-captures/`. Все Auth/Flutter-тесты запускаются без облачной конфигурации и внешней сети через `tool/checks_without_cloud.sh`.
