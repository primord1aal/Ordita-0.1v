## Исправленная заставка

Причина старого вида: темы `values-v31` и `values-night-v31` задавали `#101923` и салатовый `@drawable/ic_orbita`. До Android 12 использовался launcher icon, а тёмный NormalTheme также сохранял старый фон.

- Добавлен отдельный `ic_orbita_splash.xml` с геометрией `#orbita-sign` из `design/orbita-concept.html`: скруглённая плитка, эллипс 21×14 с поворотом −43°, толщина 3.5, терракотовая точка (47.4;17.7), радиус 5.1.
- Светлая палитра: фон `#F1F1E8`, плитка `#29382F`, кольцо `#FAFAF4`, акцент `#A6533A`. Тёмная: фон `#23241F`, плитка `#F2F0E5`, кольцо `#23241F`, акцент `#E39272`. Совпадает с утверждёнными welcome-снимками и Flutter-палитрой.
- Оба `launch_background.xml` и системные темы Android 12+ ссылаются на новый знак. `NormalTheme` использует тот же фон во время передачи управления Flutter. Системные панели Android 12+ получают подходящий фон и контрастные значки.
- Для Android 12+ выбран вариант без фона системной иконки: холст 288 dp, безопасная круглая область 192 dp, знак 96×96 dp целиком внутри неё. Та же геометрия 96 dp используется до API 31. Ограничения: [Android SplashScreen](https://developer.android.com/develop/ui/views/launch/splash-screen).
- Нативная системная заставка показывает знак по правилам Android; слово «орбита.», подпись и индикатор появляются на существующем Flutter welcome-экране. Их компоновка не менялась. Нативный day/night следует системной теме; сохранённая вручную тема Flutter может отличаться от системной.

Launcher icon, уведомления, Android-служба, разрешения, manifest и принятый Flutter-дизайн не изменялись. В Dart изменена только строка версии. Старый drawable не удалён из других ресурсов, но больше не используется заставкой.

## Конфигурация и готовность тестового Supabase

После добавления Supabase получены URL и единственный включённый современный publishable-ключ `orbita-mobile-test`. Идентификатор совпал с утверждённым `fjqghohhohgvwlmefdmo`; запрещённый ref определён по существующему `orbita-dev` в списке проектов. К запрещённому проекту запросы данных не выполнялись. Подготовлены все четыре входных параметра действующего guard:

```text
SUPABASE_TEST_URL
SUPABASE_TEST_PUBLISHABLE_KEY
SUPABASE_TEST_PROJECT_REF
SUPABASE_FORBIDDEN_PROJECT_REF
```

`write_test_config.dart` успешно проверил точный HTTPS-домен, разрешённый/запрещённый ref и формат ключа. Вне Git, в RAM-файле с правами 0600, созданы только три клиентских defines; запрещённый ref исключён. Реальный публичный ключ в исходники и отчёт не записан. GitHub Variables не изменялись: прежний HTTP 403 на их чтение больше не блокирует получение конфигурации напрямую из Supabase.

Проверено на целевом тестовом проекте:

- `/auth/v1/health` и `/auth/v1/settings` — HTTP 200 с выбранной публичной конфигурацией; email-вход включён, подтверждение email требуется, регистрация отключена.
- `orbita_get_access()` существует, возвращает JSONB с ожидаемыми полями, STABLE / SECURITY DEFINER; выполнение разрешено `authenticated`, запрещено `anon`.
- Есть активные незаблокированные подтверждённые аккаунты с паролем: пассажир — 1, водитель — 1, администраторы — 2. Прочитаны только агрегаты, без адресов email, UUID, паролей или их хешей.
- Две ограниченные SQL-проверки выполнялись в `BEGIN READ ONLY` с таймаутом 5 секунд и завершались `ROLLBACK`. База, аккаунты, роли, SQL/миграции и настройки Supabase не изменялись.

Эти проверки подтверждают конфигурацию и наличие необходимых серверных предпосылок. Последующая приёмка приложения в обеих ролях подтверждена владельцем и записана выше; пароли агенту не передавались, обхода Auth нет.

Полный набор из 375 Flutter-тестов пройден для предыдущего исправления. В этом изменении он повторно не запускался: рабочий Flutter-код, авторизация и роли не менялись. После выдачи APK владелец подтвердил физическую приёмку сборки в обоих режимах.

## Установка и проверка на Tecno KL7

1. Скачать новый APK по ссылке выше и сверить SHA-256. Если сейчас установлена выданная 0.5.7+9, сертификат тот же, versionCode повышен. Открыть APK штатным установщиком и обновить поверх. Для согласованного USB-устройства: `adb install -r ORBITA-0.5.8+10-arm64-debug.apk`.
2. При отказе подписи/версии сохранить сообщение ошибки и остановиться: старое приложение и данные не удалять, понижение версии не принуждать.
3. Проверить холодный запуск при системных светлой и тёмной темах: новый фирменный знак, без старой салатовой заставки. Убедиться, что отображается версия 0.5.8 / сборка 10.
4. Войти существующей тестовой учётной записью пассажира: после серверной проверки должен открыться пассажирский экран с картой и адресами. Выйти и войти существующим водителем: должен открыться экран «Линия» с вкладками «Поездки» и «Профиль». Роли выбирает сервер. Настоящая водительская линия остаётся отключённой в ранее согласованном объёме.
5. Проверить выход, повторный вход и восстановление сессии после перезапуска. При ошибке передать текст ошибки/снимок без паролей и токенов. Полученный результат приёмки владельцем записан в начале отчёта; агент не выдаёт его за собственные испытания телефона.
