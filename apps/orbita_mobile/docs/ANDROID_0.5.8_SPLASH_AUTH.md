# Android 0.5.8+10: заставка и блокер подключённой сборки

Ветка: `codex/orbita-flutter-design-integration`. База: `fd404cd61b171f91d4bfc0576c8e93a1a3e2c369`. Дата: 12 ноября 2026 года.

**Новый APK не собран и не опубликован.** Конфигурация существующего `orbita-mobile-test` недоступна этой среде. Исправление заставки подготовлено отдельно; кандидат версии повышен до 0.5.8+10.

## Исправленная заставка

Причина старого вида: темы `values-v31` и `values-night-v31` задавали `#101923` и салатовый `@drawable/ic_orbita`. До Android 12 использовался launcher icon, а тёмный NormalTheme также сохранял старый фон.

- Добавлен отдельный `ic_orbita_splash.xml` с геометрией `#orbita-sign` из `design/orbita-concept.html`: скруглённая плитка, эллипс 21×14 с поворотом −43°, толщина 3.5, терракотовая точка (47.4;17.7), радиус 5.1.
- Светлая палитра: фон `#F1F1E8`, плитка `#29382F`, кольцо `#FAFAF4`, акцент `#A6533A`. Тёмная: фон `#23241F`, плитка `#F2F0E5`, кольцо `#23241F`, акцент `#E39272`. Совпадает с утверждёнными welcome-снимками и Flutter-палитрой.
- Оба `launch_background.xml` и системные темы Android 12+ ссылаются на новый знак. `NormalTheme` использует тот же фон во время передачи управления Flutter. Системные панели Android 12+ получают подходящий фон и контрастные значки.
- Для Android 12+ выбран вариант без фона системной иконки: холст 288 dp, безопасная круглая область 192 dp, знак 96×96 dp целиком внутри неё. Та же геометрия 96 dp используется до API 31. Ограничения: [Android SplashScreen](https://developer.android.com/develop/ui/views/launch/splash-screen).
- Нативная системная заставка показывает знак по правилам Android; слово «орбита.», подпись и индикатор появляются на существующем Flutter welcome-экране. Их компоновка не менялась. Нативный day/night следует системной теме; сохранённая вручную тема Flutter может отличаться от системной.

Launcher icon, уведомления, Android-служба, разрешения, manifest и принятый Flutter-дизайн не изменялись. В Dart изменена только строка версии. Старый drawable не удалён из других ресурсов, но больше не используется заставкой.

## Подтверждённый блокер

В переменных текущей среды отсутствуют все четыре параметра:

```text
SUPABASE_TEST_URL
SUPABASE_TEST_PUBLISHABLE_KEY
SUPABASE_TEST_PROJECT_REF
SUPABASE_FORBIDDEN_PROJECT_REF
```

Чтение каждого соответствующего GitHub Repository Variable завершилось ошибкой интеграции; отдельная проверка подтвердила ответ **HTTP 403, `Resource not accessible by integration`**. Это ограничение доступа текущей интеграции, а не доказательство отсутствия Variables в репозитории.

Действующий `write_test_config.dart` при отсутствующих параметрах возвращает код 1 и не создаёт файл клиентских defines. Его защита не обходилась. Новая неподключённая сборка не запускалась.

Нужно предоставить эти четыре значения через защищённую конфигурацию исполнительной среды либо разрешить интеграции только чтение существующих Repository Variables. Не менять сами GitHub Variables, Supabase, аккаунты или роли. Значения ключей и пароли не передавать через чат, Git или отчёт. Нужен только публичный `sb_publishable_…`, не серверный ключ.

Пока параметры недоступны, настоящие Auth, наличие `orbita_get_access` и назначение тестовых ролей не проверены. Они не объявляются ни работающими, ни отсутствующими. Проверки с искусственными данными не подтверждают настоящий вход.

## Выполненные проверки

- AAPT2 36.0.0: компиляция всех Android `res/` и связывание с Android SDK 36 — успешно. Прочитана итоговая таблица ресурсов: светлые/тёмные цвета, `LaunchTheme` и `NormalTheme`, варианты API 31 с новым drawable. Это проверка ресурсов, не сборка устанавливаемого APK и не снимок телефона.
- Целевой `backend_configuration_test.dart`: **17 успешно, 0 ошибок**. Первый запуск не смог начать тесты из-за нехватки места во временном каталоге; повтор с `TMPDIR` в оперативной памяти успешен, код между запусками не менялся.
- `dart tool/test_build_guard.dart`: разрешённая искусственная конфигурация, запрет другого проекта/отсутствующих параметров и удаление старого файла — успешно.
- Реальный preflight без доступной конфигурации: ожидаемый отказ (код 1), файл defines не создан.
- `dart format --output=none --set-exit-if-changed lib/src/ui/theme.dart`: без изменений.
- Существующий debug-ключ сохранён; SHA-256 его публичного сертификата совпадает с APK 0.5.7+9: `36e06fba301fdca7928c8e20b120f24dcc49647b7997565597950feba2f6771f`. Новый сертификат не создавался. Это подготовительная проверка; метаданных нового APK пока нет.

Полный набор из 375 Flutter-тестов пройден для предыдущего исправления. В этом изменении он повторно не запускался: рабочий Flutter-код, авторизация и роли не менялись. На физическом Android новая заставка ещё не проверена.

## Действия после снятия блокера

1. Проверить четыре параметра действующим `TestBackendConfiguration` через `write_test_config.dart`, включая точное соответствие URL разрешённому ref и отличие запрещённого ref. Файл defines хранить вне Git, не включать запрещённый ref в APK.
2. Проверить доступность целевого тестового Auth с публичной конфигурацией. Настоящий вход и `orbita_get_access` проверять существующими разрешёнными учётными записями; при отсутствии функции/назначенной роли остановиться, ничего не создавать автоматически.
3. Только затем собрать ARM64 debug APK 0.5.8+10 с `--dart-define-from-file`, проверить manifest/versionCode/архитектуру/подпись/SHA-256 и отсутствие серверных ключей. Сверить подпись с прошлым APK.
4. Согласовать доступный владельцу способ передачи подключённого APK. Не публиковать его в общедоступную ветку или тег без отдельного согласия. Пока подключённый файл не существует, ссылка на старый APK не выдаётся за новый результат.
5. На Tecno KL7 при совместимых версии и подписи установить поверх без удаления приложения или данных. Проверить холодный запуск в системных светлой/тёмной темах; для существующих тестовых пассажира и водителя — настоящий вход, соответствующий роли экран, выход и повторный вход. Пароли и токены не включать в журнал. Подтверждение этих сценариев записать отдельно от факта компиляции.
